The coding agents we use every day — Claude Code, Cursor, Codex — are, at their core, surprisingly simple things: an LLM plus a harness. The LLM is the brain. The harness is the body that lets that brain actually do work. It's the system prompt that defines how the model behaves, the tools that let it read files and run commands, the loop that maintains conversation state, the machinery that manages context windows and token caches. The same GPT-5.5 scores 61.5% in OpenAI's Codex harness and 87.2% in Cursor's. Same brain, different body, very different outcomes.

The complication is that these coding agents are evolving at terrifying speed. Tasks that demanded carefully hand-crafted pipelines a year ago now resolve in a single prompt. Vercel reported that removing 80% of the tools they'd wired into their agent actually improved it — fewer steps, fewer tokens, faster responses. A late-2025 Stanford HAI study was even more blunt: once you're past a reasonable baseline, further prompt refinement improves output quality by less than 3%.

### The Bitter Lesson, one level up

What we're watching is Richard Sutton's Bitter Lesson play out, almost verbatim, one level up the stack. Sutton's line, distilled: throughout AI's history, hand-crafted structure has consistently lost to general methods that scale with compute and data. The clever workarounds we built to paper over the model's weaknesses — the elaborate system prompts, the "think step by step" nudges, the painstaking tool decompositions — get absorbed into the next model release. The harness you carefully built yesterday becomes the friction that drags down the same coding agent today.

### Where the model stops

So is harness engineering a fool's errand? No. Because there's an entire class of knowledge the model cannot learn, no matter how many parameters or tokens you throw at it. Your company's internal wiki. Your team's code conventions. Your industry's regulations. Who is authorized to approve what. Which actions a human needs to sign off on. None of this lives inside the model, and none of it ever will. As models gain more autonomy, deciding the limits of that autonomy — and verifying its outputs — becomes more important, not less.

### The harness splits in two

The conclusion, then, is simple. The harness doesn't disappear. It splits into two.

One kind is the harness that compensates for the model's weaknesses. This kind is on borrowed time. As the model improves, the workaround gets absorbed. If you're going to build this kind, build it to be ripped out — keep it thin, keep the seams clean, never get attached.

The other kind is the harness that wires the model into your organization and environment. Internal tools, proprietary data, permissions, approval workflows, domain expertise. This kind doesn't shrink as the model gets smarter; if anything, it grows, because a smarter, more autonomous agent needs a richer set of guardrails, a richer map of where it's allowed to operate.

### The question to keep asking

If you're building harness today, the question to keep asking yourself is this: am I patching a weakness the model is about to fix on its own, or am I bridging the model to something it can never learn? If it's the former, build it thin and disposable. If it's the latter, you're building a real asset.

Jarvis isn't Jarvis because the underlying model is brilliant. Jarvis is Jarvis because of the vast harness infrastructure around it — the suit, the house, the weapons systems, the data, the permissions to act on all of them. Jarvis is not the end of harness engineering. Jarvis is its destination.
